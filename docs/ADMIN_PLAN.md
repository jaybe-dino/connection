# 어드민(운영자 콘솔) 기획 v1.0

커넥션 내부 총괄 표면 — 브랜드 콘솔·크리에이터 앱에 이은 **네 번째 표면**.
인계 기획안 §7 플랫폼 갭(분쟁 처리 P0 · 운영자 콘솔 P1 · 아리 품질 모니터링 P1)을
상세 기획으로 확정한다. 원칙: **아리가 못 푸는 일은 결국 사람에게 온다** —
어드민은 그 사람의 작업대다.

| 항목 | 내용 |
|---|---|
| 주소 | `admin.connection.app` — 데스크톱 웹 (콘솔과 동일 스택: Vite+React) |
| 접근 | 운영자 계정 전용 · 2FA 필수 · 전 행동 감사 로그(원장 기록) |
| 성격 | 심판(분쟁·신고) + 안전망(어뷰징·아리 오작동) + 관제(수집엔진·품질·매출) |

## 1. 역할과 권한

| 역할 | 누가 | 할 수 있는 것 |
|---|---|---|
| **총괄(Super)** | 대표 | 전부 + 운영자 계정 관리 + 브랜드/크리에이터 정지 + 아리 강제 개입 |
| **국가 운영자** | TH/VN 파트타임 (M1~) | 담당 국가의 신고 처리 · 분쟁 1차 판정 · 셀 개입 |
| **CS/신고 처리** | 창업팀(M0)→채용 | 신고함 처리 · 크리에이터 문의 대응. 정지 권한 없음(요청만) |
| **재무** | 대표 겸임(M0) | 정산 관제 · 과금 조정 · 환불. 커뮤니티 개입 없음 |
| 읽기 전용 | 감사·투자 보고용 | 대시보드·리포트 열람만 |

권한 원칙은 브랜드 콘솔 팀 권한과 동일 철학 — **역할 + 행동별 지정**, 모든
파괴적 행동(정지·삭제·번복)은 원장에 actor와 함께 기록되고 되돌림도 기록된다.

## 2. 화면 맵 (스프린트 백로그)

우선순위: **P0 = 서비스 열기 전 필수** · P1 = 첫 분기 · P2 = 이후.

### ① 대시보드 — 총괄 지표 `P1`
전 브랜드 합산: 브랜드 수·플랜 분포 / 활성 크리에이터·신규 가입 / 셀 발화 추이 /
캠페인 퍼널(등록→선정→제출→통과) / 이번 달 매출(구독+가입 과금) /
수집엔진 요약(母 DB 순증·계정당 원가·수렴률 — `harvest.metrics` 스냅샷 그대로).

### ② 신고 처리함 `P0` ★
크리에이터 앱의 "메시지 신고" 버튼이 도착하는 곳. 이거 없이 커뮤니티를 열면 안 된다.
- 큐: 신고 항목(메시지 원문+번역 · 신고 사유 · 아리 1차 분류: 스팸/괴롭힘/기타·심각도)
- 조치: 기각 / 경고(당사자 통지) / 메시지 숨김 / 셀 정지 7일 / 계정 정지 — 조치별 원장 기록
- SLA: 심각(괴롭힘·혐오) 24시간 내, 그 외 72시간 내
- 반복 신고자·반복 피신고자 자동 플래그

### ③ 분쟁 심판 `P0` ★
브랜드↔크리에이터 사이에 커넥션이 심판으로 서는 절차. 유형 3:
| 유형 | 접수 경로 | 판정 기준 |
|---|---|---|
| 검수 이의 | 크리에이터가 보완요청에 이의 | 캠페인 조건 원문(원문 우선 원칙) 대조 |
| 정산 불일치 | 지급 금액·시점 다툼 | 원장 대조 — append-only라 증거가 그대로 있다 |
| 선정 번복 | 브랜드가 선정 취소 | 배송 전=허용(사유 기록) / 배송 후=보상 지급 |

절차: 접수 → 24h 내 1차 응답 → 양측 소명(담당자 스레드) → 72h 내 판정 →
원장 기록(`DISPUTE_OPENED`/`DISPUTE_RESOLVED` — core에 이미 정의됨) → 이의는 1회, 총괄이 최종.

### ④ 어뷰징 대응 `P0`
- 리퍼럴 사기: 동일 기기 3계정 플래그(기획 §4.3) → 코드 정지·보상 회수
- 가짜 계정: 판정 엔진의 REJECT 사유 열람 · 수동 정지/복구
- **dedup 사람 검토 큐**: 병합 점수 0.6~1.0 건 판정(동일인/별개) — DB 테이블은 이미 있음(`dedup_review_queue`)

### ⑤ 아리 품질 모니터링 `P1`
구독 갱신의 근거 데이터. 브랜드별:
- 브라이어 성적표(채널별 30일 채점 — `core.evaluation.channel_report` 그대로 노출)
- 게이트 반려율(브랜드가 아리 제안을 얼마나 거절하나 — 높으면 학습 이상 신호)
- L2 승격/강등 관리: 컷 통과 채널 승격 승인, 사고 시 강등(전부 원장 기록)
- 아리 강제 개입: 특정 브랜드 아리 일시정지 · 발화 재생성 · 프로필 롤백

### ⑥ 브랜드 관리 `P1`
목록(플랜·상태·갱신일) / 온보딩 지원(학습 막힌 브랜드 도움) / 플랜 변경·정지 /
청구 이력. Enterprise 배타권 설정.

### ⑦ 크리에이터 관리 `P1`
전 브랜드 관점의 크리에이터 뷰(브랜드 콘솔은 자기 멤버만 본다) — 계정 상태 ·
정지/복구 · 데이터 삭제 요청 처리(PDPA/GDPR — 철회 전파 실행 확인) · 문의 이력.

### ⑧ 수집엔진 관제 `P0(운영 시작과 동시)` ★
이미 구현된 엔진의 조종석:
- 지표 대시보드: `metrics.snapshot()` — 순증·원가·수렴률·벤더 실패율·경보
- dead_letter 재처리 버튼 · 수렴/예산 파라미터 조정
- **아웃리치 중단 관리**: 스팸 점수 초과로 자동 중단(`SequencePaused`)된 엔진의
  원인 보고 확인 → 사람이 `resume()` — 이 승인 UI가 여기다
- 벤더 크레딧 잔량·소진 예상

### ⑨ 정산 관제 `P1`
플랫폼 수익 원장(구독·가입 과금) / 브랜드별 미수 / 크리에이터 지급 실패 재처리 /
환불 처리(원장 역기재 아님 — 상계 이벤트 추가).

### ⑩ 시스템 `P1`
운영자 계정·역할 관리 / 감사 로그 열람(원장 필터 뷰) / 공지·점검 모드.

## 3. 데이터 모델 추가분

기존 스키마 재사용이 원칙 — 신규는 3테이블뿐:

```sql
admin_users   (admin_id, name, role, countries[], totp_secret, active)
reports       (report_id, cell_id, msg_id, reporter, reason, ai_class,
               severity, status, action, handled_by, sla_due, created_at)
disputes      (dispute_id, kind, brand_id, creator_id, campaign_id,
               state[open→responded→resolved→appealed→final],
               opened_at, first_response_due, verdict_due, verdict, decided_by)
```
조치·판정·정지·재개는 전부 기존 **원장(ledger)** 에 이벤트로 기록 —
`DISPUTE_OPENED/RESOLVED`는 core에 이미 정의돼 있고, 신고·정지용 이벤트 타입만 추가.

## 4. 기존 구현과의 연결 (새로 만들 게 적다)

| 어드민 화면 | 이미 있는 것 |
|---|---|
| 신고함 | 크리에이터 앱 신고 UI · 알림 시스템 |
| 분쟁 심판 | 원장(증거) · DISPUTE 이벤트 타입 · 담당자 1:1 스레드 |
| 어뷰징 | `judgment.py` 4축 사유 · `dedup_review_queue` 테이블 |
| 아리 품질 | `core/evaluation.py`(브라이어·L2 컷·리포트) 전부 |
| 수집엔진 관제 | `harvest/metrics.py` · `scheduler.status()` · `OutreachEngine.stats()/resume()` |
| 감사 로그 | append-only 원장 + 무결성 검증 API |

→ 어드민 콘솔의 본질은 **이미 구현된 도메인 로직의 운영 UI**다. 백엔드 추가는
신고/분쟁 테이블 + 어드민 인증 정도.

## 5. 로드맵 반영

- **M0 (서비스 오픈 전)**: 신고 처리함 + 분쟁 절차(간이 — 접수는 폼, 처리는 어드민) +
  어뷰징 기본 + 수집엔진 관제. 어드민 인증은 창업팀 2~3계정.
- **M1**: 대시보드 · 브랜드/크리에이터 관리 · 정산 관제 · 국가 운영자 역할.
- **M2**: 아리 품질 모니터링 자동화 · 갱신 리포트 · 읽기 전용 역할.

## 6. 오픈 이슈

1. 신고 처리 언어 — 태국어 신고를 한국 운영자가 보나? → 아리 번역+요약 자동 첨부로 해결(번역 레이어 재사용)
2. 분쟁 판정의 법적 지위 — 약관에 "커넥션 중재 절차 우선 동의" 명시 필요(법무)
3. 정지 계정의 정산 — 미지급 보상은 판정 확정 후 지급/몰수 기준 필요
4. 어드민 접근 보안 — 2FA는 M0부터, IP 제한·SSO는 팀 커지면
