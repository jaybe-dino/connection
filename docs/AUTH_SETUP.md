# 실인증 체계 — 사용 가이드

> 브랜드: 이메일+비밀번호 / 크리에이터: 이메일 매직링크 / 어드민: 비밀번호+OTP(2FA)
> 세션: JWT 24시간. 전환기에는 기존 간이 키(?key=)와 병행 — `AUTH_REQUIRED=1`을
> 켜는 순간 전면 강제(간이 키 차단)된다.

## 🧑 최초 1회 — 어드민 계정 만들기 (2분)

1. `https://admin.theprlist.net` 접속 → "최초 어드민 계정을 만듭니다" 화면
2. 이메일 + 비밀번호(10자 이상) 입력 → **어드민 만들기**
   - 이미 로그인 화면이 뜨면 → 누군가 만든 것. 그 계정으로 로그인.
3. (권장) 2단계 인증 켜기 — 현재는 API로:
   로그인 후 `POST /auth/otp/setup` → 받은 `otpauthUri`를 구글 OTP 앱에 등록
   → `POST /auth/otp/enable {code}` . (어드민 화면 버튼은 다음 배포에 추가)

## 브랜드 계정 흐름 (자동)

- 어드민이 **가입 신청 승인** → 신청서의 담당자 이메일로 **초대 링크**(72시간)가 만들어짐
  - 지금(메일 발송 전)은 승인 응답의 `inviteLink`를 어드민이 복사해 전달
- 브랜드가 링크 열기 → 비밀번호 설정 → 계정 활성화
- 이후 콘솔(console.theprlist.net) 좌하단 **🔐 로그인** 칩으로 로그인
  → 자기 브랜드의 지메일 연결·해제 등 민감 동작 권한이 생김 (남의 브랜드는 403)

## 크리에이터 로그인 (매직링크)

- 크리에이터 앱 좌하단 🔐 → 이메일 입력 → 받은 링크 클릭(15분 유효) → 로그인
- 계정이 없으면 자동 생성(가입 겸용). 비밀번호 없음.

## Railway 환경변수

| 변수 | 값 | 언제 |
|---|---|---|
| `JWT_SECRET` | 긴 무작위 문자열 (예: `openssl rand -hex 32`) | **지금 권장** — 없으면 ADMIN_KEY를 서명키로 씀 |
| `SITE_URL` | `https://theprlist.net` | 초대·매직링크 주소에 사용 (기본값이 이미 이것) |
| `AUTH_REQUIRED` | `1` | 파일럿 브랜드 온보딩이 끝나 전면 강제할 때 |

## 기술 요약 (감사용)

- 비밀번호: scrypt(n=2^14) + 16B 솔트, 원문 미저장
- 토큰: JWT HS256, 24h 만료 / 매직링크·초대는 해시만 DB 저장, 1회용+만료
- 2FA: RFC 6238 TOTP (구글 OTP 호환, ±30초 허용)
- 가드: 어드민 라우트(JWT admin 또는 전환기 키), 브랜드 민감 라우트(그 브랜드
  JWT/어드민 JWT/전환기 키), OAuth state HMAC 서명은 기존대로
- 모든 계정 이벤트는 원장에 기록 (BOOTSTRAPPED/INVITED/ACTIVATED/2FA_ENABLED/LOGIN)

## 멀티테넌시 (완료)

- 브랜드 스코프 API(발신자·지메일·인박스·발송 배치) 전면 격리 — 자기 브랜드
  JWT만 통과, 타 브랜드는 403, 어드민은 전체 접근. AUTH_REQUIRED=1이면 무인증 차단.
- 콘솔은 로그인한 계정의 브랜드로 동작(미로그인 시 데모 glowlab)
- 데모 브랜드(glowlab·aura)는 `brands.is_demo=true` 표시. 실서비스 DB를
  깨끗하게 시작하려면 `DEMO_SEED=0` (기본은 데모 시드 유지 — 영업 시연용)

## 남은 것 (다음 배포)

- 어드민 화면에 2FA 설정 버튼·로그아웃 버튼
- 초대·매직링크 실메일 발송 (지메일/SendGrid 연동 지점은 코드에 표시됨)
- 가입 위저드에 담당자 이메일 입력칸(현재 데모 파리티로 고정값) → 승인 시 그 주소로 초대
- 발송 배치 CSV 링크(export.csv)의 토큰화 (현재 배치 ID가 무작위 캐퍼빌리티)
