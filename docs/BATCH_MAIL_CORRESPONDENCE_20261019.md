# 단체 발송 → 수신자별 원문·회신 → 개별 작성

- 어드민 /recruitment → 발송 내역 → ‘수신자별 발송·회신 관리’.
- 배치별 브랜드/제품/발신 주소/제안 코드와 수신 주소·Gmail 접수·회신 확인·확인 필요를 구분한다. 50명 페이지, 이메일 검색, 회신 대상/대기/확인 필요 필터 제공.
- ‘발송 원문·회신 보기’는 recipient.provider_id + 해당 Gmail 계정 + 회사 공간 + 이메일에 일치하는 실제 mail_messages 원문을 조회한다. 준비 문안 재조합을 실제 전송 증거로 표시하지 않는다. 원문을 대조하지 못한 경우 ‘저장된 제안 문안 · 실제 발송 원문 아님’으로 표시.
- 회신은 같은 계정·Gmail 대화이며 발송 이후 수신 원문만 연결한다. 이메일만 같고 Gmail 대화가 다른 회신은 합치지 않는다. 같은 Gmail 대화에 제안이 여러 개 있으면 제안별 인과 귀속은 확인되지 않으므로 중복 합산/신청 전환으로 간주하지 않는다.
- 회신의 ‘이 회신에 직접 답장 작성’은 메일함 계정·정확한 이메일·받은 메일 ID를 전달해 개별 작성기로 이동한다. 오래된 회신도 정확한 ID로 다시 조회하며 다른 계정 ID는 거부한다.
- 계정·스레드 고정, 초안 저장, 발송 별도 확인, 수신거부/한도/불명 결과 재발송 금지 유지. 실제 모집 이메일 발송 없음.
- AI 답장 작성은 제공자/키 선택 대기. 기존 Anthropic 키는 있으나 실제 요청에서 잔액 부족 확인됨. OpenAI 키는 운영에 없음. 기존 Claude 유지·충전 또는 OpenAI 새 키 설정 선택을 사용자에게 요청했다. 임의 새 키/제공자 전환이나 AI 기능 완료 주장을 하지 않음.

로컬 합성 기록으로 배치→수신자→저장 원문+같은 Gmail 회신→원래 계정의 정확한 회신 작성기 연결을 검수. 서버/API 테스트에서 별도 대화 제외, 회사/고객 격리, 미발송 문안 구분, 정확한 회신 ID의 다른 계정 접근 거부를 검수.
