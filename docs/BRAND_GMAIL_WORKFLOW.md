# 브랜드별 Gmail 연결·발송·수신 운영 절차

1. 브랜드 담당자가 theprlist 콘솔에 해당 브랜드 계정으로 로그인합니다.
2. 메일링에서 **Google 발송·수신 권한 연결**을 누르고 브랜드 전용 Gmail/Google Workspace 계정을 선택합니다. 서비스 로그인과 이메일 접근 동의는 별도입니다.
3. Google에서 발송 및 받은 메일 읽기를 허용하고 콘솔을 새로고침합니다. 기존 발송 전용 연결은 재동의해야 합니다. 동일 이메일은 다른 브랜드에 중복 연결할 수 없습니다.
4. **동기화**를 누릅니다. 최근 30일 받은편지함에서 최신 10개를 매번 먼저 확인합니다. 이전 메일의 다음 페이지가 있으면 10개를 추가 확인합니다(호출당 최대 2페이지). 자기 주소로 보낸 메일도 받은편지함에 있으면 수신으로 가져오며, 보낸편지함에만 있는 메일은 제외합니다. 메일링 화면이 열려 있으면 60초마다 동기화합니다. 서버에서 `RUNNER_ENABLED=1` 또는 `GMAIL_OPS_ENABLED=1`로 Gmail 운영 루프를 활성화한 경우, 실제 Google 연결과 읽기 동의가 있는 브랜드를 화면과 무관하게 최소 10분 간격으로 동기화합니다. 기능이 구현되어 있다는 사실만으로 운영 루프의 활성화·성공을 판단하지 말고 관리자 운영 상태의 마지막 실행·오류를 확인합니다.
5. 아웃리치 초안을 확인해 직접 발송합니다. 받은 메일에 대한 답장은 해당 수신 계정으로 보내고 Gmail 대화 식별자와 회신 헤더를 포함합니다. 브랜드별 계정·메일 접근을 제한하며 다른 브랜드의 메일은 조회하거나 발송할 수 없습니다.
6. 연결 해제하면 추가 동기화와 발송이 중단됩니다. 이미 저장된 메일은 연결 해제만으로 삭제되지 않습니다. 삭제 요청은 개인정보처리방침의 연락처로 접수합니다.

## 범위와 제한

- 저장 항목: 발신자·수신자, 제목, 본문 텍스트, 메일 시각, Gmail 메시지/대화 ID. 첨부파일을 가져오지 않습니다. HTML은 텍스트로 변환합니다.
- Gmail 읽음/삭제 상태를 변경하지 않으며 첨부파일 확인과 원본 관리는 Gmail에서 합니다.
- 동일 메시지는 중복 저장하지 않습니다. 콘솔 대화는 현재 연락처별로 묶이며 답장은 가장 최근 수신 메일의 Gmail 대화로 연결됩니다.
- 수신 본문은 이 동기화 기능에서 AI 제공자에게 전송하지 않습니다. 관심/거절 분류는 로컬 규칙입니다.
- 워밍업은 실제 발송일 기준 2→4→6→8→12→16→20통으로 제한합니다. 도달률 개선을 보장하거나 가짜 상호 메일을 생성하지 않습니다. 발송 결과가 불확실하면 자동 재발송하지 않습니다.
- 동기화 실패 시 연결 상태와 권한을 확인하고 재연결합니다. 실제 수신·답장 검증은 수신 권한 동의 후 별도로 수행해야 합니다.

## 운영자 Google 설정

- Gmail API 활성화, OAuth 웹 앱 콜백: `https://api.theprlist.net/gmail/callback`
- 범위: `openid`, `email`, `https://www.googleapis.com/auth/gmail.send`, `https://www.googleapis.com/auth/gmail.readonly`
- 테스트 모드에서는 참여 브랜드 이메일을 테스트 사용자로 등록합니다. 공개 서비스 전에는 Google의 제한된 범위 검증 및 서버 저장에 따른 보안 평가 요건을 확인해야 합니다.
- Railway: GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, GOOGLE_REDIRECT_URI, TOKEN_ENC_KEY. 기존 암호화 키를 임의 변경하지 않습니다.
- Gmail 운영 루프는 수신 동기화 외에 사람이 승인한 배치의 발송 재개도 수행합니다. 수신만 검수하려면 `GMAIL_SEND_RESUME_ENABLED=0`으로 발송 재개를 차단한 상태인지 확인합니다. 이 문서의 안내만으로 운영 설정을 변경하지 않습니다.
- 참조: https://developers.google.com/workspace/gmail/api/auth/scopes

## 공개 검증 제출 준비

다음은 제출 준비 항목이며 Google 승인 완료를 뜻하지 않습니다.

- 앱 홈페이지·개인정보처리방침·이용약관의 브랜드명, 연락처, 실제 저장 항목과 삭제 절차를 운영 화면과 대조합니다. 브랜드 담당자가 계정 연결 전에 읽기·발송 범위와 서버 저장을 알 수 있어야 합니다.
- `gmail.send` 사용 목적: 브랜드가 검토·승인한 크리에이터 모집 메일과 받은 문의의 답장을 연결한 브랜드 이메일 계정으로 발송합니다.
- `gmail.readonly` 사용 목적: 해당 브랜드의 받은편지함에서 최근 30일의 문의와 회신 본문을 콘솔에 보여주고 대화로 관리합니다. 제목·발신자만 제공하는 범위로는 본문 읽기를 제공할 수 없습니다. 첨부파일은 수집하지 않으며 Gmail의 삭제·읽음 상태는 변경하지 않습니다.
- 검증 영상에는 브랜드 로그인 → 이메일 접근 목적 고지 → Google 계정 선택과 실제 요청 범위 → 연결된 계정 표시 → 자기 주소를 이용한 발송·수신·답장 → 연결 해제를 보여줍니다. 토큰·비밀키와 다른 고객 메일을 영상에 노출하지 않습니다. 실제 동의·수신을 하지 않은 화면을 성공 증빙으로 사용하지 않습니다.
- 제한 범위로 얻은 메일을 서버에서 저장·전송하므로 Google의 보안 평가 요건을 확인하고 필요한 평가 자료를 준비합니다. 범위 등록, 앱 게시, Google 검증 승인, 보안 평가는 각각 별도 상태로 기록합니다.
- 공개 게시·검증 제출은 실제로 필요한 증빙과 담당자 정보를 준비한 후 진행합니다. 테스트 모드 연결 성공만으로 일반 브랜드의 공개 이용 가능을 안내하지 않습니다.
