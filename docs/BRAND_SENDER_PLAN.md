# 브랜드 발신 이메일 등록 시스템 + 대량 발송 가이드 — 기획 v1

> 브랜드사가 **자기 회사 이메일(예: marketing@glowlab.kr)을 직접 등록·인증**하고,
> 그 이름으로 아웃리치·알림 메일이 나가게 하는 시스템.
> 스프레이류 "대량 발송 준비 가이드"를 콘솔 안에 온보딩으로 내장한다.

---

## 1. 왜 브랜드별 발신 이메일인가

지금 구조(커넥션 공용 도메인 하나로 전 브랜드 발송)의 문제:

| 문제 | 결과 |
|---|---|
| **평판 공유** | 한 브랜드가 스팸 신고 먹으면 **모든 브랜드** 메일이 스팸함행 |
| **수신자 신뢰** | 크리에이터가 모르는 도메인에서 온 메일 → 열람률↓ 신고율↑ |
| **법적 발신자** | 발신 주체가 불분명 — 스팸법(정통망법·CAN-SPAM)상 발신자 명시 의무 |
| **회신 단절** | 크리에이터가 답장하면 브랜드가 아니라 우리한테 옴 |

**브랜드별 자체 발신으로 바꾸면**: 평판 격리(사고가 나도 그 브랜드만 정지),
브랜드 이름으로 도착(신뢰·회신율↑), 발신 주체 명확. 우리는 인프라와 가드레일만 제공.

## 2. 브랜드 온보딩 플로우 (콘솔 → 설정 → "발신 이메일")

```
STEP 1  이메일 등록        marketing@glowlab.kr 입력
   ↓                      → 그 주소로 6자리 인증코드 발송 → 입력 → 소유 확인 ✓
STEP 2  도메인 인증        시스템이 SPF·DKIM·DMARC용 DNS 레코드를 자동 생성해
   ↓                      복사 버튼과 함께 표시 + "도메인 관리자에게 보내기" 버튼
                          → DNS 반영을 10분 주기 폴링 → 완료 시 초록 배지 ✓
STEP 3  발신 프로필        발신자 이름(GLOWLAB 파트너십팀) · 회신 주소 · 서명
   ↓                      · 수신거부 문구(자동 삽입, 편집 불가 영역)
STEP 4  워밍업 시작        자동: 일 20통 → 매일 ×1.2 → 상한 도달까지 2~4주
   ↓                      진행 게이지 + "오늘 보낼 수 있는 양" 표시
STEP 5  발송 가능          아웃리치·알림이 이 주소로 발송 (게이트는 그대로 유지)
```

- **STEP 2까지가 필수**, 미완료 브랜드는 "커넥션 공용 발신(제한 모드)"으로만
  소량 발송 가능 — 온보딩을 미루면 손해라는 걸 화면에서 체감하게.
- 서브도메인 권장을 UI에서 안내: **알림은 mail.브랜드도메인, 아웃리치는 outreach.브랜드도메인**
  (아웃리치 평판 하락이 거래 메일을 죽이지 않도록 — 가이드 §5에 이유 설명)

## 3. 브랜드별 평판 대시보드 + 자동 가드레일

콘솔 설정 페이지에 발신 건강 지표:

| 지표 | 경고 | 자동 조치 |
|---|---|---|
| 반송률(bounce) | 3%↑ | 5%↑ → 발송 일시정지 + 리스트 재검증 요구 |
| 신고율(complaint) | 0.05%↑ | 0.1%↑ → 발송 정지 + 사람 확인 필요 (기존 서킷브레이커를 브랜드별로) |
| 열람률 | 15%↓ | 아리가 제목·문안 개선 제안 |
| 워밍업 준수 | — | 상한 초과 시도는 큐에 자동 대기 (거부 아님) |

모든 정지·재개는 원장 기록(`SENDER_PAUSED`/`SENDER_RESUMED`). 재개는 사람 승인.

## 4. 데이터 모델 (마이그레이션 006)

```sql
brand_senders (
  sender_id, brand_id, email, domain, kind,          -- kind: outreach | notify
  state,        -- unverified → email_verified → dns_pending → active → paused
  from_name, reply_to, signature,
  dns_records jsonb,          -- 표시용 SPF/DKIM/DMARC 레코드 (ESP 발급값)
  esp_ref,                    -- SendGrid 등 ESP 쪽 도메인 인증 ID
  warmup_started_at, daily_cap,
  bounce_rate, complaint_rate, open_rate,            -- 롤링 30일
  created_at, verified_at
)
sender_events (sender_id, type, detail, at)          -- 인증·정지·재개 이력
```

- 발송 엔진 연동: `OutreachEngine`을 브랜드별 인스턴스로 (워밍업·상한·억제 목록이
  브랜드 단위), ESP 어댑터에 발신 프로필 주입. suppression은 브랜드별 + 전역 2중.

## 5. 브랜드용 가이드 문서 (콘솔 내장 + 공개 페이지)

스프레이식 구성으로 "대량 발송 시작 전 준비" 가이드를 제공 — 온보딩 각 스텝 옆
`?` 아이콘으로 해당 섹션이 열리게:

1. **왜 아무 메일함에서 바로 보내면 안 되나** — 발신 평판 개념, 스팸함 직행 원리
2. **도메인 준비** — 서브도메인 분리(mail./outreach.)를 권하는 이유, 새 도메인 주의점
3. **DNS 인증 3종 쉽게 이해하기** — SPF(보낼 자격)·DKIM(위조 방지 서명)·DMARC(정책),
   "복사해서 도메인 업체 관리 화면에 붙여넣기만 하면 됩니다" 수준의 절차 + 대표
   업체별(가비아·카페24·Cloudflare) 스크린샷 자리
4. **워밍업은 왜 2~4주인가** — 하루 20통부터 늘리는 이유, 서두르면 생기는 일
5. **콘텐츠 규칙** — 수신거부 링크 필수, 스팸 트리거 표현(무료!·100%·과도한 이모지),
   이미지만 있는 메일 금지, 아리 검토가 발송 전 자동 체크하는 항목 목록
6. **지표 읽는 법** — 반송·신고·열람률 기준선과 우리 자동 가드레일 설명

→ 가이드는 4개 언어(ko·en·th·vi) — 기존 번역 파이프라인 재사용.

## 6. 개발 순서

1. **P0-1** 마이그레이션 006 + 등록/인증 API (이메일 코드 인증 → 상태 머신) + 테스트
2. **P0-2** 콘솔 "설정 → 발신 이메일" 화면: 4스텝 위저드 + 상태 배지 + DNS 레코드 카드
3. **P0-3** SendGrid 도메인 인증 API 연동 (브랜드별 domain authentication 생성·검증 폴링)
   — SENDGRID_API_KEY 없으면 데모 모드(가짜 레코드·수동 확인 버튼)로 동작
4. **P0-4** 발송 엔진 브랜드별 분리(워밍업·상한·평판) + 가드레일 + 러너 연동
5. **P1** 가이드 문서 4개 언어 + 공개 가이드 페이지 + 평판 대시보드 카드
6. **P2** Instagram DM 등 채널 확장은 별도 기획 (DM은 플랫폼 정책 리스크가 커서
   틱톡샵 공식 초대(대량발송 기획)와 셀 내 소통을 우선하는 게 안전)

## 7. 사장님(운영) 준비물

- SendGrid 계정 + API 키 (브랜드별 도메인 인증을 우리 계정 아래 생성하는 구조)
- 커넥션 자체 도메인 확정 (공용 발신 폴백 + 가이드 페이지 호스팅)
- 가이드 3번 섹션용: 가비아/카페24 DNS 설정 화면 스크린샷 (실계정 캡처)
