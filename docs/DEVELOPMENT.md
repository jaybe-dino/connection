# 커넥션 개발 계획

인계 패키지(`docs/handover/`) 기준의 개발 준비 · 진행 문서.
기준 문서: 서비스기획안 v1.0 (§7 갭 분석, §8 로드맵) · 페이지맵 · 수집엔진 구현상세 명세.

## 스택 결정

인계 문서의 가이드("프로토타입은 화면 스펙의 정본, 프레임워크는 팀 선택")에 따라:

| 영역 | 선택 | 근거 |
|------|------|------|
| 수집 엔진 | **Python 3.11** + PostgreSQL + Redis(큐) | 구현상세 명세의 파이프라인/의사코드와 1:1 대응. 순수 로직(스코어·판정·dedup)은 stdlib로 구현해 테스트 가능. |
| 母 DB | **PostgreSQL** (주 원장) + 파생 인덱스 | 기술스택 명세 §5 그대로. |
| 프론트엔드 | **pnpm workspace + Vite + React 18 + TypeScript** | 앱 3표면 공통. `packages/shared`(타입·목데이터) + `packages/ui`(토큰·컴포넌트) 공유. |
| 크리에이터 앱 | PWA (React) — manifest + SW 포함 | 같은 URL · 홈화면 설치 · 푸시. |
| 브랜드 콘솔 | 데스크톱 웹 (React) | 나란히 구조 — 레일(8) + 아리 채팅 + 캔버스. |
| 공통 레이어 | **services/core (Python)** — 게이트 엔진 · append-only 원장(해시 체인) · 동의(철회 전파) · 브랜드 프로필 버전 · 알림 | 페이지맵 "공통 시스템 레이어". |

디자인 토큰(`packages/ui/src/tokens.css`)은 프로토타입 클릭데모의 팔레트를 추출한 것
— 웜 뉴트럴 + 테라코타(액션) + 세이지(승인) + 앰버(보류) + 플럼(아리).

수집엔진과 앱은 **독립 병행** — 수집엔진 MVP는 앱과 별개로 먼저 돌릴 수 있다
(연결점은 母 DB → 후보 큐).

## 현재 구현 상태

### ✅ 완료 (이 저장소)

- 인계 문서 통합 (`docs/handover/`)
- DB 스키마 (`db/migrations/`)
  - `001_creator_pool.sql` — 母 DB 30+ 필드 + dedup 검토 큐 · 병합 원장 · 수렴 상태 · dead_letter
  - `002_core.sql` — 게이트 · append-only 원장(UPDATE/DELETE 차단 트리거) · 동의 · 재접촉 금지 · 브랜드 프로필 버전 · 팀 권한 · 알림
- 수집엔진 (`services/harvest/`, 테스트 68개):
  - **discover/workers** — 시드 사전 · 수렴 판정 · 일일 예산 · D1 해시태그 워커 · D2 그래프 확장 워커(fanout cap)
  - **fetch** — 벤더 라우터(우선순위/폴백) · 배치/재시도 규칙(§4)
  - **vendors** — ScrapeCreators·EnsembleData·Apify·Lamatok HTTP 어댑터(키는 환경변수, 응답 normalize 포함)
  - **http** — stdlib 트랜스포트 · 토큰 버킷 레이트 리미터 · 지수 백오프 재시도
  - **enrich** — 이메일 추출 3단(난독화 대응) · 검증 파이프 · 국가 판정 가중 합의 · link-in-bio 크롤러
  - **dedup / score / queues / store / pipeline** — §6·§7·§2 그대로
- 공통 레이어 (`services/core/`, 테스트 27개):
  - **gates** — 4종 게이트 상태기계 (승인=실행 · 보류=외부 무통지 · 팀 역할/게이트별 권한)
  - **ledger** — append-only 해시 체인 원장 + 무결성 검증
  - **consent** — 필수 3종+선택 · 브랜드별 2종 · 철회 즉시 전파(실패 시 전 발송 정지) · 90일 재접촉 금지
  - **brand_profile** — 버전 관리 · 학습(5문항 확인) 없이는 모집 불가 게이트
  - **notifications** — 알림함 + 유형별 채널 설정 · 브랜드 승인 대기 외부 알림
- 앱 3표면 (`apps/`, 전부 타입체크+빌드+렌더 검증):
  - **creator-app** — PWA(manifest·SW) · 셀(3채널·원문 칩·신고) · 담당자(셀 스위처·1:1) · 캠페인(배송 추적 스텝) · 제출(자동 체크 4종·원클릭 보정) · 정산(PingPong 온보딩) · 내 패스(본인 수정·동의·언어 변경) · 알림함(유형별 푸시 설정)
  - **console** — 레일 8 + 아리 채팅 패널(캔버스 점프) · 브리핑 · 승인함(게이트 4종 승인/보류/거절) · 발굴수집(에이전트 8종) · 셀(대화/활성화/충원/규칙) · DB(세그먼트·보유 필드와 근거) · 캠페인(등록·지원자·배송 관리) · 검수 · 원장 · 설정(팀 권한)
  - **signup** — 5단계 위저드 (사업자 조회 → 슬러그·국가 → 플랜 → 사이트 학습+5문항 → 완료, 학습 미완 시 진행 불가)
  - `packages/shared`(도메인 타입·목데이터) · `packages/ui`(토큰·공용 컴포넌트)

### 로드맵 (기획안 §8)

- **M0 · 검증 (~2개월)** — 브랜드 1곳 · 태국 셀 1개 · 아리 L0~L1. OAuth 가입 + 셀 + 유가 캠페인 1종 + 수동 정산. 즉시 P0: 신고/차단 · 언어 변경 · 기본 알림(메일). 성공: 셀 30명 · 4주 발화 유지 · 판정 정확도 80%↑
- **M1 · 반자동 (3~5개월)** — 인바운드 판정·스윕 L2 · 채점 루프 · P0 완성. 성공: 브랜드 3곳 · 승인 평균 4시간 내
- **M2 · 자동+확장 (6개월~)** — L2 승격(브라이어) · 어필리에이트 엔진 · 리포트 · 두 번째 국가. 성공: 브랜드 10곳 · 갱신율 80%↑

## 수집엔진 운영 파라미터 (설계 기준값)

구현상세 명세의 숫자 — 운영에서 캘리브레이션. 코드의 `harvest/config.py`에 반영.

- 그래프 확장: `seed_pages_per_tag=50`, `commenters_per_video=top3×200`, `suggested_depth=2hop`, `expand_fanout_cap=30/계정`
- 수렴 판정: 최근 10k 중 신규율 < 3%가 3배치 연속 → 전수 근접으로 종료
- Fetch: `batch_size=500`, 재시도 3회 지수 백오프(2s→8s→30s), 429는 감속+벤더 폴백, 404는 즉시 `EXCLUDED`
- 국가 판정 가중치: account_region 0.40 · phone_country 0.25 · bio_lang 0.15 · caption_lang 0.15 · active_hour_tz 0.05, conf<0.6 → recheck
- Dedup: 합산 ≥1.0 자동 병합 · 0.6~1.0 사람 검토
- 비용 목표: 계정당 30~120원 (100만 계정 워크드: API 직접비 ~$21,000~35,000 + 라이선스)

## 하지 않는 것

- 자체 LLM · 파인튜닝 (라벨 1만 건 전) / 범용 CRM / 반출·라이선스 기능 (범위 제외)
- 로그인 우회 · CAPTCHA 무력화 · ToS 위반 스크래핑
- 탐색 피드 · 셀 랭킹 (셀은 브랜드 단독 세계)
