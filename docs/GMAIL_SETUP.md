# 지메일 연동 셋업 — 구글 클라우드 콘솔 (클릭 단위 가이드)

> 브랜드사가 콘솔에서 "구글로 연결" 한 번으로 자기 회사 지메일 명의 발송을 켜는 기능.
> 이 문서는 그 전제가 되는 **우리(디노스튜디오) 쪽 구글 앱 등록** 절차다.
>
> **심사 최소화 설계**: 권한은 `gmail.send`(보내기) 하나만 쓴다.
> 받은편지함 읽기 권한은 구글 "제한 등급"이라 연 1회 유료 보안점검(CASA)이 붙는데,
> 우리는 답장을 Reply-To 전용 주소로 우리 서버에 직접 받으므로 필요 없다.
> → 일반 심사(무료, 2~6주)로 끝난다. 심사 전에도 **테스트 사용자 100명**까지 정상 동작.

## 1. 프로젝트 만들기 (5분)

1. https://console.cloud.google.com 접속 (회사 구글 계정으로)
2. 상단 프로젝트 선택 드롭다운 → **새 프로젝트** → 이름 `connection` → 만들기
3. 왼쪽 메뉴 **API 및 서비스 → 라이브러리** → `Gmail API` 검색 → **사용 설정**

## 2. OAuth 동의 화면 (10분)

1. **API 및 서비스 → OAuth 동의 화면**
2. User Type: **외부(External)** 선택 → 만들기
3. 입력:
   - 앱 이름: `커넥션 (Connection)`
   - 사용자 지원 이메일: 회사 이메일
   - (도메인 확정 후) 앱 도메인·개인정보처리방침 URL — 심사 제출 전까진 비워도 됨
4. **범위(Scopes)** 단계 → 범위 추가 → 아래 2개만 체크:
   - `https://www.googleapis.com/auth/gmail.send`  ← 이것만 민감 등급
   - `openid`, `email` (기본 — 연결된 주소 확인용)
   - ⚠️ `gmail.readonly` / `gmail.modify` 는 **절대 추가하지 않기** (CASA 대상)
5. **테스트 사용자** 단계 → 본인 지메일 + 파일럿 브랜드 담당자 지메일 추가 (최대 100명)

## 3. OAuth 클라이언트 ID 발급 (5분)

1. **API 및 서비스 → 사용자 인증 정보** → **+ 사용자 인증 정보 만들기** → **OAuth 클라이언트 ID**
2. 애플리케이션 유형: **웹 애플리케이션**, 이름 `connection-api`
3. **승인된 리디렉션 URI**에 추가:
   ```
   https://connectioncreator-app-production.up.railway.app/gmail/callback
   ```
   (도메인 확정 후 `https://api.<도메인>/gmail/callback` 도 추가)
4. 만들기 → **클라이언트 ID / 클라이언트 보안 비밀**이 표시됨

## 4. Railway에 등록 (2분) — ⚠️ 키는 채팅에 올리지 않기

Railway → api 서비스 → **Variables**:

| 변수 | 값 |
|---|---|
| `GOOGLE_CLIENT_ID` | 3번에서 받은 클라이언트 ID |
| `GOOGLE_CLIENT_SECRET` | 3번에서 받은 보안 비밀 |
| `GOOGLE_REDIRECT_URI` | 3번에 넣은 리디렉션 URI 그대로 |
| `TOKEN_ENC_KEY` | 토큰 암호화 키 — 터미널에서 `python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` 로 생성 (또는 Claude에게 "토큰 키 생성 명령 알려줘") |

저장 → 자동 재배포 → 콘솔 메일링 탭의 지메일 카드가 "구글로 연결" 실모드로 바뀐다.

## 5. 동작 확인 (3분)

1. 콘솔 → 발굴·수집 → **메일링** 탭 → 지메일 카드 → **구글로 연결**
2. 구글 로그인 창 → 테스트 사용자로 등록한 지메일 → "허용"
3. "✅ 지메일 연결 완료" 화면 → 콘솔 새로고침 → 연결됨 카드 확인
4. 발송은 전부 **승인함(OUTBOUND 게이트)** 을 거친다 — 승인 전엔 아무것도 안 나감

## 6. (도메인·약관 준비 후) 심사 제출

1. OAuth 동의 화면 → **앱 게시(Publish)** → 확인 → **심사 제출(Submit for verification)**
2. 제출물: 앱 도메인, 개인정보처리방침 URL, 데모 영상(연결 흐름 1~2분 녹화),
   각 범위 사용 사유 한 줄 — "브랜드가 자기 지메일 명의로 크리에이터에게 협업 제안을 보내기 위함"
3. 심사 중에도 테스트 사용자는 계속 정상 동작 → 파일럿에 지장 없음

## 답장 인박스는 어떻게 받나 (참고)

- 발신 메일의 Reply-To = `reply+<브랜드>@reply.<도메인>` (환경변수 `REPLY_DOMAIN`)
- 크리에이터가 답장 → 그 주소로 수신 → 인바운드 파서(SendGrid Inbound Parse,
  SendGrid 가입 후 설정)가 `POST /inbound/reply` 로 전달 → 콘솔 인박스에 표시
- 아리가 답장을 관심/거절/질문으로 1차 분류, 답장 발송은 게이트 승인 후

## 일일 한도(자동)

연결 첫날 20통 → 매일 ×1.2 → 최대 450통(지메일 계정 한도 보호).
한도 초과분은 도메인 트랙(SendGrid)으로 자동 폴백된다.
