# 계정별 메일함·회신자 관리

## 어디서 사용하는가
https://admin.theprlist.net/recruitment → 크리에이터·메일.

1. 메일 계정에서 실제 주소 선택. ‘전체 계정’은 명시적 통합 보기이며, 개별 계정 선택 시 목록·원문·이전 페이지·미분류 수신 원문을 해당 계정으로 제한한다.
2. ‘이 계정 회신 가져오기’는 선택 계정만 동기화한다. 연결 상태·읽기 권한·마지막 가져오기·수신/발신 오류·발송 중지 정보를 표시한다. ‘전체 계정’에서는 기존 읽기 권한을 가진 모든 계정에 적용.
3. 기본 분류는 ‘회신 온 크리에이터’. 답장 필요/새 수신/발송만 한 대상/답장 초안/결과 확인/전체 기록을 별도 관리한다. 숫자는 해당 계정의 등록된 고유 이메일 수이며 실인원·스레드·총 메일 건수가 아니다. 검색·진행 상태는 목록에 추가 적용한다.
4. 답장 필요는 같은 계정·같은 Gmail 대화의 실제 발송 기록을 기준으로 한다. 초안 저장·취소·다른 대화의 발송은 미응답을 해제하지 않는다. 발송 접수는 배달 성공 증명이 아니다.
5. 연락처에서 해당 계정의 수신·발신 원문, 발신 주소와 상대방을 확인한다. ‘이 받은 메일에 답장’ → 초안 저장 → 별도 검토·확인 체크 → 실제 1통 발송. 원래 Gmail 계정·스레드·RFC 답장 기준을 유지한다. 한 크리에이터의 다른 계정 이력이 오래된 정상 대화를 막지 않도록, 해당 계정·Gmail 대화의 발신 증거를 확인한다. 다른 계정으로 자동 전환하지 않는다.
6. ‘표시된 받은 메일 읽음 처리’는 본 화면에 조회된 메일까지 운영팀 공통 읽음으로 저장한다. Gmail read-only 권한을 유지하며 실제 Gmail 읽음/보관/삭제 상태는 바꾸지 않는다. 조회 후 들어온 새 메일은 과거 읽음 요청으로 지워지지 않는다.
7. 담당자·진행 상태·다음 행동·기한·메모·제안/신청 이력은 크리에이터 공통 CRM으로 명시한다. 다른 주소를 동일인으로 자동 병합하지 않는다. 계정별 원문과 공통 CRM은 구분한다.
8. 미분류 받은 메일은 별도 영역에서 계정별·50개 페이지로 검토한다. 실제 모집 대화인지 원문을 확인해야 연락처로 등록한다. 보안 알림/일반 업무 메일을 회신 크리에이터로 자동 계산하지 않는다.

## 동기화 범위
- 최근30일, 계정당 최신10통+기존 커서10통의 제한된 수신 페이지와 발신 페이지. 남은 페이지가 있으면 다시 가져온다. 기존 백그라운드 수신 동기화는 유지하며, 이 메일함의 가져오기 동작은 발신 대조를 함께 수행한다.
- 보낸 메일은 이미 CRM에 등록된 크리에이터와의 기존 대화, 현재 계정과 일치하는 발신자, 단일 To/Cc/Bcc 수신자만 반입한다. 무관한 업무 메일·불명확한 다중 수신 메일·별칭 발신 전체를 무조건 합치지 않는다.
- 기존 Gmail message ID로 중복을 막는다. 외부에서 보낸 답장도 동일 Gmail 대화로 저장돼 답장 필요 판단에 반영된다.
- 발신 반입 실패는 별도 savepoint·계정별 지속 오류 기록. 수신 반입은 보존하고 다른 계정에 오류를 전파하지 않는다. 모든 과거 Gmail·첨부파일·별칭/그룹 메일의 완전한 Gmail 클라이언트 복제는 아니다.

## 권한과 보존
053은 계정별 운영팀 읽음 커서와 발신 동기화 커서/오류, 인덱스를 추가한다. 연락처·원문·계정·제안·과금 기록을 삭제하지 않는다. OAuth 범위/발송 한도/계정 중지/수신거부/불명 결과 재전송 금지를 유지한다. 관리자 JWT가 없거나 다른 고객 브랜드 계정을 지정하면 접근 불가.
