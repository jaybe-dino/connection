# theprlist 오픈 준비 현황 체크리스트 (2026-09-26 개정)

검증을 세 층위로 구분한다. **아래 어느 층위의 통과도 단독으로 "공개
오픈 완료"를 뜻하지 않는다** — 3층(운영 실증)까지 확인된 항목만 실사용
준비가 입증된 것이다.

## 1층 — 개발 완료 (격리 DB·모사 기반 코드 테스트)

커밋 이력과 `docs/DEV_STATUS_2026-09-20.md`에 테스트 증거와 함께 기록.
서버 pytest·tests_billing·tests_ui·signup 단위·로컬 Playwright E2E가
여기에 해당한다. 외부 서비스는 전부 모사이므로 실연동을 증명하지 않는다.

## 2층 — 배포 확인 (운영에 코드가 실려 있는가)

배포 후 아무 머신에서:

```bash
EXPECT_COMMIT=<배포한 커밋 sha> bash scripts/ops/open-check.sh
```

읽기 전용(GET만): API·DB 정상, 배포 커밋 일치(/health의 commit),
콘솔·크리에이터 앱의 최신 엔진 마커, 소개 사이트의 매직 전달 코드,
러너 수신 동기화 활성 + 승인 자동 발송 차단. FAIL이면 각 줄의 사유대로
조치(대부분 재배포 또는 Railway 환경변수).

## 3층 — 운영 실증 (실계정·실데이터로 사람이 확인)

### 실증 완료 (Codex 운영 검수 기록)

- 매직링크 실메일: app origin 랜딩·brand 보존·로그인/새로고침 유지
- 관리자 콘솔: 명시 브랜드 선택, QA5 제품/캠페인/커뮤니티/메일 격리
- AI 실사용(크레딧 충전 후): 홈페이지 본문 실분석→profile 저장, 선택
  제품 반영 영어 AI 초안, 커뮤니티 글 한국어→일본어 실번역
- Gmail 실수신 동기화·수동 답장 발송(운영 계정)

### 실증 없음 — 오픈 판단 전 확인 필요

- **신규 브랜드 Gmail OAuth 실연동**: 코드·오류처리 회귀만 통과.
  실동의 화면 경유 연결은 미실증 (운영 Google Cloud가 조직 본인인증
  진행 중).
- **NICEpay 실결제**: 결제/대사/취소통지 반영은 격리 테스트만 통과.
  실카드 승인·정산·취소는 미실증 (운영 NICEpay 콘솔 로그아웃 상태).
- **TikTok 실연동**: 미실증.
- **후보 추천 데이터 품질**: email_status=valid·수신거부 제외 필터를
  통과하는 후보가 실DB에 충분한지, 추천 품질이 쓸 만한지 미확인
  (후보 0건은 필터 결과였음 — 전체 DB 0건 아님).
- 기존 실패 번역 글: 재시도 UI 배포 후 실제 재시도로 해소 확인.

## 진행 중 남은 실증의 성격

위 미실증 항목은 코드 결함이 아니라 **외부 계정/데이터 상태**(조직
인증, PG 로그인, 후보 수집량)에 걸려 있다. 각 항목이 풀리는 대로
Codex 운영 검수로 실증하고 이 문서를 갱신한다. 문제 발견 시: 증상을
이 저장소 브랜치(claude/dev-progress-prep-6n810t) 작업 세션에 전달
→ 수정 → 재검수.
