# 공용 모집 운영 보완 — 2026-10-18

## 운영 흐름

`고객 브랜드 → 제품·USP 근거 → 모집 매핑·제안 코드 → DB 집군 추천 → 발신 계정 분산 검수 → 초안 저장 → 별도 발송 승인 → 회신 작업함 → 고객 브랜드 신청·커뮤니티 → 성과·원가`

공용 운영 주체와 고객 브랜드 귀속은 분리한다. 이번 변경은 기존 브랜드 콘솔과 크리에이터 커뮤니티 UI를 교체하지 않는다. 계정당 rolling 24시간 200건·최소 60초, 기존 대화 발신 고정, 승인 큐 범위와 수신거부를 유지한다. 오늘 사용 가능한 제공자 한도·실제 배달·일 1만 명 달성으로 표현하지 않는다.

## 새 어드민 기능

주소: `https://admin.theprlist.net/recruitment`

1. 제품 매핑을 선택한다. 국가·언어는 ISO 코드인 경우 집군 필터에 기본 입력된다. 제품별 USP와 근거는 기존 브랜드 콘솔의 제품 프로필 기능을 사용한다.
2. **집군 추천**에서 국가·언어·분류·태그·팔로워 범위·추천 수(1~1,000)를 정한다. 신규 모집과 기존 관계의 다음 제품 검토를 구분한다. 기존 `identity_group`과 정규화 이메일 중복을 제거한다. 이는 검증된 실인원 수가 아니다. 미검증 주소는 기본 제외하며 명시적으로 검토에 포함할 수 있다. 이 동작은 운영 연락처 반입·유료 AI 호출을 하지 않는다.
3. 집군을 일괄 선택해 아래 발신 분산 검수로 넘긴다. 발신 주소를 드래그하거나 체크박스로 선택한다. 배정 전 원래 발신자·연결·중지·예약·잔여량·수신거부·최근 연락을 검사한다. 초안 저장은 실제 발송 승인이 아니다.
4. 제안 코드는 매핑 UUID와 개정 번호로 생성한다. 저장한 배치는 당시 코드를 보존한다. 매핑 변경 후 예전 제안의 코드·문안·대상은 바꾸지 않는다. 일반 직접 초안은 배치 UUID 코드로 구분한다. 과거 코드 없는 배치는 미기록으로 표시한다.
5. **회신 작업함**에서 실제 수신 메일의 추천 분류를 검토한다. 관심·유료만·조건부·국가 부적합·거절·수신거부·주소 오류·질문 등을 확정하고 담당자·다음 행동·기한·메모를 저장한다. 동시 수정은 개정 충돌로 차단한다. 답장 초안은 원래 발신 계정으로 저장하고 별도 승인을 기다린다. 자동 답장 발송은 하지 않는다.

   실제 공용 발신 이력이 있는 대화만 모집 회신 작업함에 포함한다. 운영 검수에서 발신 이력과 연결되지 않은 수신 대화 54개를 관측했으며, 이를 모집 회신으로 세지 않도록 미연결 수신 수로 따로 표시한다. 기존 일반 인박스나 수신 원문을 삭제하지 않는다.
6. **반송·차단**에서 증빙과 수신자 기록 ID를 연결한다. 일반 텍스트 메일을 반송으로 간주하지 않는다. 구조화된 영구 실패 DSN의 실제 발신 계정·수신자·Gmail 스레드가 정확히 일치할 때만 자동 차단한다. 그 외 반송·불만은 관리자 확인 근거가 필요하다. 영구 반송·불만·운영자 연락 중지는 전체 발신에서 차단한다.
7. 확인된 불만은 해당 발신 계정을 즉시 중지한다. 최근 24시간 접수 20건 이상, 영구 반송 3건 이상, 반송률 3% 이상이면 계정을 중지한다. 자동 재개·다른 발신자로 우회하지 않는다. 이는 모든 제공자의 FBL 자동 수신이 구현됐다는 뜻이 아니다.
8. **전환·원가**에서 주간·월간 등의 날짜 범위를 KST [시작일, 종료일 미만)으로 조회한다. 브랜드별 합계와 전체 고유 인원을 별도로 보여준다. 비용·매출은 항목·기간·근거를 입력해 기록하며 요청 ID로 중복 저장을 막는다. 실제 결제와 수금은 실행하지 않는다.

## 집계 해석

- 발송 처리 상태 행과 실제 네트워크 시도 수는 다르다. 정확한 네트워크 시도 원장은 기존 데이터에서 복원할 수 없어 미집계로 표시한다.
- 제공자 접수, 증빙 있는 배달, 회신, 신청, 합의, 출고, 콘텐츠 링크 제출을 구분한다.
- 회신은 같은 발신 계정·Gmail 스레드·기존 발송 메시지가 연결될 때만 귀속한다. 같은 스레드에서 여러 브랜드를 제안했다면 가장 최근의 실제 발송 제안 한 곳에만 귀속한다.
- 신청·합의·출고·콘텐츠 링크는 기간 내 신청 집군의 현재 상태다. 해당 기간에 모든 후속 단계가 발생했다는 뜻이 아니다.
- 브랜드별 고유 크리에이터 수의 합과 전체 고유 크리에이터 수는 다를 수 있다. 캠페인별 참여 조합 수는 별도다.
- 배송 수령·실제 게시·판매는 아직 신뢰할 입력 연동이 없어 null로 표시한다. 콘텐츠 URL 제출을 실제 게시로 바꾸어 계산하지 않는다.
- 비용·매출은 조회 기간에 완전히 포함된 근거 기록만 합산한다. 미기록을 0으로 보지 않는다. 기록 원가/신청자는 비용 기록이 있을 때만 계산한다.
- 검증 가입 5,000원 사용량은 별도 표시한다. 아웃리치 매출·실제 수금으로 합산하지 않는다. 기존 중복 과금 규칙은 변경하지 않았다.

## API·데이터

- `POST /admin/recruitment/mappings/{id}/cohort`: 읽기 전용 집군 추천.
- `GET /admin/recruitment/inbox`, `PUT /admin/recruitment/inbox/{thread_id}`: 관리자 공용 회신 작업함.
- `POST /inbox/threads/{thread_id}/reply`: 기존 답장 초안 게이트 재사용.
- `POST /admin/recruitment/feedback`, `GET /admin/recruitment/safety`: 증빙·차단·중지.
- `GET /admin/recruitment/metrics`: 기간·브랜드별 집계.
- `POST /admin/recruitment/costs`: 근거 있는 비용·매출 기록.

모든 새 운영 경로는 관리자 JWT·OTP 완료 상태를 검사한다. 고객 브랜드와 크리에이터에게 전사 DB·대화·비용을 노출하지 않는다. 마이그레이션 047은 제안 코드 컬럼·운영 기록 테이블·인덱스 추가만 수행한다. 기존 연락처·가입·청구·승인 배치를 변경하는 데이터 백필은 없다.
