# 테스트 메일과 브랜드 커뮤니티 운영

## 사용 경로

`https://admin.theprlist.net/recruitment` → **테스트 발송**.
브랜드·제품 제안, 회사 발신 계정, 받을 회사 메일을 선택 → 미리보기 → 실제 테스트 1통 확인 체크 → 보내기.
기본 수신자는 chief@dinostudio.kr. 수신자는 공용 공간에 연결된 회사 메일 또는 이 chief 주소로 한정한다.
메일 제목에 [TEST], 본문에 내부 테스트 표시. 테스트는 모집 대상·신청·멤버십·청구를 생성하지 않는다.
일반 브랜드 신청 페이지를 확인하는 링크이며 수신자별 application 토큰을 만들지 않는다. 실제 모집 배치는 기존 토큰·캠페인 귀속 경로를 그대로 사용한다. 제품·캠페인 값은 검수 문안/URL에 포함하지만 일반 브랜드 링크만으로 특정 캠페인 신청 저장을 시험했다고 주장하지 않는다.

Gmail의 제공자 접수는 배달 보장이 아니다. 테스트 기록의 accepted는 Gmail이 message ID를 반환했다는 의미다. Gmail 실제 발송 경로와 시스템 한도(rolling 24h), 예약분, 60초 간격, 중지·수신거부·반송 차단을 적용한다. 일반 신규 가입 게이트가 대기 상태여도 내부 메일 확인은 가능하다. 이것은 모집 제한을 해제하지 않는다.

요청 ID를 먼저 DB에 커밋한 뒤 제공자를 호출한다. 결과 불명/타임아웃은 review에 두고 계정을 중지한다. 동일 ID로 결과를 확인해도 재전송하지 않는다. sending에 남은 요청도 자동 재전송하지 않는다. 운영자가 Gmail 보낸편지함을 대조하고 기존 Gmail 운영 화면에서 계정 상태를 검토한다. 자동 재시도·계정 교체는 없다.

## 브랜드 승인·커뮤니티

같은 모집 화면의 **브랜드 승인·커뮤니티** 메뉴에서 고객 브랜드별 기본 방·관리 계정·실제 회원·제품 수·브랜드 링크를 확인한다. 방 이름 저장은 기존 방을 보존하고 누락된 기본 방만 멱등 생성한다. 고정 채널은 잡담/촬영 팁/공지, 멤버십/DM 권한 검사는 현행 /community API를 유지한다. 방 생성과 멤버십/검증가입/청구는 별개다.

메뉴 아래 실제 대기 중인 브랜드 신청을 검토·승인한다. 승인 시 브랜드·기본 커뮤니티·담당자 owner 역할을 생성하고 초대 링크를 **console.theprlist.net**으로 연결한다. 초대 메일은 자동 전송하지 않는다. 이미 회사 관리로 등록된 브랜드를 다시 신청·승인할 필요는 없다. 계약·재고·제공 조건이 미확정된 제품을 확정된 것으로 표시하지 않는다.

050 마이그레이션은 테스트 전용 기록 테이블 추가와 기존 recruitment_brand_setup 회사 관리 브랜드의 누락 기본 방 보완만 수행한다. 기존 방 이름·메시지·회원·발송·과금 기록은 변경하지 않는다.

## 검수와 한계

새 API 검수 7개: 관리자 권한/회사 수신자, 읽기 전용 미리보기, 명시 승인/멱등/모집 분리, 불명 결과 재전송 금지/계정 중지, 개정/수신거부, 한도/중지, 승인 후 실제 방·owner·콘솔 링크.
로컬 가상 2브랜드에서 테스트 미리보기와 방 이름 저장·재조회를 UI로 검수. 외부 제공자 자격증명과 Gmail 운영 스위치를 끈 로컬 검수다. 실제 테스트 메일은 이 개발 작업에서 보내지 않는다.
운영 로그인 후 실제 기존 브랜드 상태와 pending 신청 확인이 필요하다. 일반 TikTok 신규 가입 인증 승인은 별도 외부 의존이다.
