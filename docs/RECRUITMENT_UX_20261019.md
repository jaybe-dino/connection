# 다중 브랜드 모집 UX 개편

## 사용 순서

운영 주소: https://admin.theprlist.net/recruitment

기본 메뉴는 모집 시작 / 반복 모집 / 발송 내역 / 회신·성과 / 브랜드·메일 설정이다. 실제 외부 발송은 이번 개발·검수에서 실행하지 않는다.

1. **새 모집 준비하기**: 등록된 제품 제안을 여러 개 선택한다. 제품·조건이 없는 브랜드는 별도 표시한다. 선택 순서가 후보 배정 우선순위이며 같은 이메일·알려진 동일인은 이 준비에서 한 제안에만 배정한다.
2. **제안 확인**: 브랜드별 문안·제공 조건과 담당자 메모를 확인한다. 제품 조건 확인 체크 후 저장하면 제안이 active가 된다. 저장은 발송이 아니다.
3. **대상 찾기**: 브랜드당 후보 수, 국가, 팔로워 범위, 신규/기존 관계, 분류·태그를 지정한다. 이메일 검증 기록이 0이면 미검증 검토 포함을 명시적으로 선택하도록 안내한다. 수집 국가로 언어를 추정하지 않는다. 내부 추천 이유와 실제 메일 첫 문장을 분리하며 개별 첫 문장을 수정할 수 있다.
4. **메일 나누기**: 사용할 발신 계정을 선택한다. 여러 브랜드의 계정 잔여량을 통합해서 배정하고 중복·거부·기존 대화 계정·신청 링크를 검수한다. 저장 시 전체 브랜드 초안을 한 트랜잭션으로 생성한다. 한 브랜드라도 저장 중 실패하면 전부 롤백한다. 결과가 불명확하면 동일 요청 ID로만 결과를 확인한다.
5. **최종 확인**: 브랜드·제품·발신자별 묶음을 열어 모든 수신자, 개인별 문안과 신청 링크를 확인한다. 실제 발송은 배치별 명시적 승인 버튼으로만 실행한다. 신규 가입 인증 준비가 안 된 현재 상태는 새 UI에서 발송을 차단하고 이유를 표시한다. 초안 취소와 이미 승인된 대기분 중지는 다른 버튼이다.

## 반복 모집

브랜드·후보 조건·메일 계정·매주/매월 준비 주기·다음 준비 날짜를 서버에 저장한다. 날짜가 되어도 자동 발송하지 않는다. 이번 회차 준비를 누르면 기존 연락처 명단·검토 결과·승인을 가져오지 않고 조건만 불러온다. 현재 제안·새 DB 집군·잔여량을 다시 확인하고 각 회차를 승인한다. 다음 주기 날짜 이동과 계획 보관은 기존 발송에 영향을 주지 않는다.

자동 예약 발송이나 미래 회차 초안 자동 생성·알림 작업은 이 기능의 범위가 아니다. 저장된 준비 날짜를 자동 발송 예약으로 표시하지 않는다.

## 검수

- 서버·청구 353개: 기존 배치·수신거부·과금·브랜드 경계 회귀 포함.
- UI 로직 83개: 이메일/identity 중복 제거, 선택 우선순위, 제안 언어와 수집 언어 분리, 월말·윤년 반복 날짜, 문안·제품·발신자·개정 보존, 내부 검수 정보의 메일 노출 방지.
- 가상 로컬 DB에서 2브랜드·2발신·8주소 → 전체 미리보기 → 4개 초안 저장 → 최종 승인 화면까지 검수. 실제 발송 안 함.
- 반복 계획 저장과 390px 모바일 렌더링 확인. 페이지 너비 390, 문서 너비 390. 일시적 뷰포트 설정 복원.
- 계정 상한 200/rolling24h, 기존 발신 고정, 수신거부·불만·반송·90일 차단, 별도 실제 발송 승인을 유지한다. 한 회차 최대 30개 제안, 총 10,000행. 발신 잔여량 초과분은 미배정으로 표시한다.

검수 관점: 회사 운영자(다중 브랜드·반복), 브랜드 담당자(제품·신청 귀속), 크리에이터(중복 제안·내부 정보 노출 방지), 보안 담당자(관리자 역할·중복 요청·중간 실패 롤백), 전달성 담당자(통합 잔여량·원래 발신자·차단), 재무 담당자(기존 청구 회귀·후보 수와 참여 인원 분리).

## 구조·호환·롤백

- 새 기본 화면: `RecruitmentWorkspace.tsx`, 기존 설정 폼은 `Recruitment.tsx`의 settingsOnly 모드로 보존. creator/console UI는 수정하지 않는다.
- `049_recruitment_repeat_plans.sql` 추가형: 반복 준비 계획과 다중 저장 멱등 기록만 추가. 실제 큐 자동 실행 없음.
- 반복 준비: `/admin/recruitment/repeat-plans` GET/POST, `/{plan_id}` PUT, `/{plan_id}/archive` POST.
- 통합 검수/저장: `/admin/recruitment/repeat-plans/multi/preview`, `/multi/drafts` POST. 관리자 JWT 전용. 실제 발송 API를 호출하지 않는다.
- 이전 개별·분산 초안 저장은 같은 트랜잭션 저장 함수를 재사용하며 기존 계약과 응답을 보존한다.
- 롤백 태그 `recruitment-ux-before-20261019`(a0172b2). DB 신규 테이블을 삭제하거나 이미 기록된 거부·발송·신청·청구를 과거 백업으로 덮지 않는다. 실제 발송 전이므로 코드 롤백은 데이터 삭제를 필요로 하지 않는다.

## 현재 외부 의존

일반 TikTok 가입 인증 심사 승인, 브랜드별 최신 제품·보상·물류·가이드 확정, 과거 외부 발송 기록 대조가 남아 있다. 새 UI가 하루 신규 1만 명 발송, 월 고유 실인원 3만 명 운영 달성을 의미하지 않는다.
