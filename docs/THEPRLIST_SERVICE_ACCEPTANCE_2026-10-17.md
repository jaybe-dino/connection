# theprlist 서비스 전환 검수 기준

상태: 개발 요청 전달·Claude 실행 시작 확인. 구현·운영 배포·최종 검수는 미완료.

## 서비스와 도메인

| 영역 | 주소 | 핵심 권한 |
| --- | --- | --- |
| 랜딩·브랜드 신청 | theprlist.net | 공개 정보·가입 신청 |
| 크리에이터 | app.theprlist.net | 본인 정보와 가입한 브랜드의 허용 공간 |
| 브랜드 | console.theprlist.net | 소속 브랜드만 운영 |
| 회사 어드민 | admin.theprlist.net | 전체 브랜드 운영·중앙 아웃리치·감사 |
| 서버 | api.theprlist.net | 모든 데이터 접근의 인증·역할·소속 검증 |

현재 디자인 기준은 preview의 slack.html v3이다. 기존 콘솔 기능을 이 디자인 구조로 통합한다. 시안의 예시 회원·메시지·XP·localStorage는 실제 서비스 데이터로 이전하지 않는다.

## 크리에이터 여정

브랜드 초대 → 이메일 로그인 → TikTok 계정 소유 인증 → 국가·언어·배송 가능 국가 → 필수 동의 → 브랜드 입장 → 캠페인 상세 → 신청 → 선정·조건 동의 → 샘플 배송 → 콘텐츠 제출 → 검수·수정 → 게시·Spark 코드 → 완료.

- 초대의 브랜드·캠페인은 로그인·이탈·재접속 후에도 유지한다.
- 이메일 인증, TikTok 소유 인증, Shop 어필리에이트 자격, 운영팀 검증은 별도 상태다.
- TikTok 취소·오류·미승인·만료·재연결 화면이 필요하다. 외부 연동 실패를 성공으로 바꾸지 않는다.
- 국가별 캠페인 조건 미충족은 사유를 표시한다.
- 다른 브랜드 커뮤니티와 비공개 협업은 URL을 알아도 접근할 수 없다.
- 공지·채팅·DM·스레드·읽음·미읽음·검색·알림·번역·원문·실패 재시도를 제공한다.
- 새 캠페인/공지 수신은 배지와 카드로 표시한다. 현재 대화를 강제로 이동시키지 않는다.
- 개인 활동과 설정, 브랜드별 랭킹·미션을 제공한다. XP는 검증된 서버 이벤트에만 중복 없이 지급한다.

## 브랜드 운영

- 브랜드 로고·기본 정보·제품·AI 분석 근거·내용 수정.
- 캠페인 초안·발행·수정·마감, 지원자 검토·선정·반려, 배송·제출·검수·완료.
- 브랜드 공지·채널·회원·DM·협업 메시지·알림·번역 관리.
- 팀원별 권한, 검증 가입 내역·월별 청구 확인.
- 서버는 요청한 brand_id와 로그인 사용자의 실제 소속을 비교한다. 화면의 브랜드 선택값만 믿지 않는다.
- 플랫폼 전체 아웃리치 권한과 타 브랜드의 연락처·대화·회원 목록은 제공하지 않는다.

## 회사 어드민

- 전체 브랜드 신청·승인·정지, 사용자·역할·캠페인·신고·감사 로그 관리.
- 중앙 모집의 대상 브랜드·제품·캠페인·발신자·발송 한도·중지·결과·전환 관리.
- 검증 가입 1명당 5,000원(부가세 포함), 월별 합산·계산서 청구 우선. 고정 구독료 없음.
- 기존 가입 과금 트리거와 중복 방지 기준을 먼저 확인한다. 새 UI 때문에 같은 가입을 재과금하지 않는다.

## 기존 코드에서 확인한 재사용 후보

운영 배포 일치 여부는 별도 확인해야 한다. 아래는 로컬 creator-community-restore 소스 관찰이다.

| 파일 | 확인한 동작 | 추가 검수 |
| --- | --- | --- |
| routes_identity.py | 브랜드 로고, 멤버십 가입, 검증 후 가입 사용량 기록 설명 | TikTok 인증 상태·과금 연결 |
| routes_recruitment_links.py | 수신자별 불투명 토큰을 해시 저장, 만료·취소·수신거부 확인 | OAuth 이후 초대 유지·반복 요청 |
| routes_recruitment_links.py | 로그인 이메일 일치, target 브랜드에만 가입·캠페인 신청 | 타 브랜드 ID 직접 요청 차단 |
| routes_outreach_bulk.py | 중앙 발신 공간과 대상 브랜드·제품·캠페인 매핑 | 외부 아웃리치 시스템 계약 합의 |
| routes_community.py / routes_collab.py | 기존 커뮤니티·협업 라우터 존재 | 역할·소속별 실제 종단 동작 |
| auth.py | JWT와 브랜드 권한 검사 도구 존재 | 모든 신규 라우트에 일관되게 적용 |

기존 불투명 토큰·해시 검증이 요구사항을 충족하면 유지한다. 새로운 서명 토큰 체계를 중복 도입할 필요는 없다.

## 중앙 아웃리치 연동 계약 초안

별도 채팅 「(아웃리치)월 3만 명 어필리에이트 운영 중요」의 정확한 링크는 확인 대기다. 협의 완료 상태가 아니다.

1. 발송 작업 공간은 중앙이며, 각 모집 건의 target_brand_id·product_id·campaign_id는 서버에서 검증한다.
2. invitation_id/불투명 초대 토큰은 특정 수신자와 대상에 묶는다. 공개 응답은 수신자 이메일을 노출하지 않는다.
3. 링크 조회·이메일 로그인만으로 멤버십 또는 비용을 생성하지 않는다. 명시적 가입·신청과 검증을 구분한다.
4. 클릭·가입·검증·캠페인 신청은 서로 다른 전환이다. UTM/source는 인증 후에도 보존한다.
5. 연동 쓰기에는 인증·서명/재전송 방지·멱등 키를 적용한다. 수신거부·중지·반송은 발송 가능 여부에 반영한다.
6. 실제 대량 발송과 3만 명 처리 성공은 이번 개발 요청만으로 검증되었다고 표시하지 않는다.

## 독립 검수: 다섯 가지 전체 여정

| 회차 | 여정 | 통과 기준 |
| --- | --- | --- |
| 1 | 신규 초대 → 인증 → 가입 → 신청 → 선정 → 제출 → 완료 | DB 저장·새로고침·역할별 상태 일치 |
| 2 | 다른 브랜드 신규 가입·모바일 전체 흐름 | 브랜드 귀속·레이아웃·배송/제출 정상 |
| 3 | 기존 회원 재초대·중복 신청·동시 요청 | 가입·지원·XP·과금 중복 없음 |
| 4 | 만료·취소·이메일 불일치·TikTok 취소·번역 실패 | 정확한 오류·복구 경로, 성공 가장 없음 |
| 5 | 브랜드 A 계정으로 B 데이터 직접 조회·수정·채팅 접근 | 서버 차단, 관리자만 명시적 전사 권한 |

PC 1440/768 및 모바일 390/375에서 크리에이터·브랜드·어드민을 검사한다. 게시한 공지·캠페인·메시지는 별도 사용자 세션에서 수신 확인한다. 테스트 이메일은 승인된 수신자만 사용하며 실제 대량 발송은 하지 않는다.

## 릴리즈 완료 기준

- 변경 커밋·원격 저장소·배포 소스가 일치한다.
- 마이그레이션·데이터 보존·롤백 방법을 확인한다.
- 필수 외부 승인·키·권한·미검증 기능을 목록으로 분리한다.
- 3개 역할의 실제 로그인·데이터 저장·수신·권한 차단을 확인한다.
- 각 운영 도메인에서 HTTPS·올바른 앱·API·OAuth 리다이렉트를 확인한다.
- 위 기준 충족 전에는 개발 완료·서비스 오픈 완료로 보고하지 않는다.
