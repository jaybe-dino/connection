커넥션 개발 인계 문서
README · 이 폴더를 어떻게 읽는가

브랜드가 소유하는 글로벌 크리에이터 커뮤니티를 에이전트가 운영하는 서비스, 커넥션의 전체 설계 패키지. 기획·화면·수집엔진을 한 번에 넘긴다. 개발 착수 전 이 README부터 읽고, 아래 읽는 순서를 따르면 된다.

START

5분 요약 — 커넥션이 뭔가

K-뷰티 브랜드는 해외 크리에이터 운영(모집·커뮤니티·검수·정산)을 사람 노가다로 한다. 커넥션은 브랜드마다 전담 운영 에이전트(아리)를 붙여 이 전 과정을 대신 굴린다. 크리에이터는 계정 하나(패스)로 여러 브랜드 커뮤니티(셀)에 소속되고, 밖으로 나가는 모든 행동(발송·정산·개인정보)은 게이트로 사람이 승인한다.

이 서비스가 성립하려면 앞단에 크리에이터를 대량으로 확보하는 수집 엔진(母 DB)이 필요하다. 목표는 국가·카테고리·제품별 50만~100만 계정. 그래서 이 패키지는 ① 서비스 ② 수집엔진 두 축으로 나뉜다.

핵심 개념한 줄 정의
패스(Pass)크리에이터 계정 1개 = N개 브랜드 멤버십. 재가입 없음.
셀(Cell)브랜드가 소유하는 크리에이터 커뮤니티 방. 상한 없음·자동 번역·브랜드 동석.
아리(Ari)브랜드별 운영 에이전트. 담당자 8종(발굴·수집)이 목표·KPI·실패조건을 가짐.
게이트(Gate)PII·정산·외부발송·공개게시 — 자율등급 무관하게 사람 승인.
母 DB수집 엔진이 채우는 전 브랜드 공유 크리에이터 원장. 母 DB→판정→초대→가입.

기술 스택 요지

  • 프로토타입은 순수 HTML/JS 데모다 — 프로덕션 프레임워크(React 등)는 팀 선택. 데모는 동작·화면 스펙의 정본으로만 쓴다.
  • 크리에이터 앱 = PWA(같은 URL·홈화면 설치·푸시). 콘솔 = 데스크톱 웹(나란히 구조).
  • 수집엔진: 구매 우선(ScrapeCreators·EnsembleData·Apify·influencers.club·TikTok Shop API) + 자체 로직(그래프확장·dedup·스코어·학습). PostgreSQL 원장 + 큐(Redis/SQS) + 워커(Temporal/Celery).
  • 공통 레이어: 인증(패스) · 번역 · 게이트 엔진 · append-only 원장 · 브랜드 프로필 · 평가 하네스 · 알림.
법률·컴플라이언스 선 — 수집은 공개 데이터·공식 API·라이선스 DB까지. 로그인 우회·CAPTCHA 무력화 안 함. 개인정보는 공개 비즈니스 연락처만, 국가별 규제(PDPA·PDPD·GDPR·州법) 처리근거·수신거부·삭제 대응 필수. 발송은 전부 게이트.
한 줄 인계 — 프로토타입으로 화면을 이해하고, 기획안으로 규칙을 이해하고, 수집엔진 4종으로 데이터 파이프라인을 짓는다. 막히면 각 문서의 결정 로그·갭 분석·오픈 이슈를 먼저 본다.
