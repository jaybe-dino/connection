02

단계 1 · Discover — 계정 후보 발견

목적: 핸들/ID 후보를 큐에 쏟아붓는다. 정확도보다 양. 소스별 어댑터가 같은 handle 출력을 낸다.

D1

해시태그 · 키워드 검색

구매
API엔드포인트/기능단가(공개)
EnsembleDatahashtag/posts · keyword/search → 영상+작성자유닛제 · 월 최소 ~$100
ScrapeCreators해시태그·검색·프로필$0.99~1.88 / 1K (대량 최저가)
Apify TikTok Scraper해시태그·검색 액터$2~6 / 1K + 월 $49
TikTok Research API/query/videos 해시태그·키워드무료 · 1,000 req/일 · 비상업
# 카테고리 해시태그 → 작성자 후보 GET ensembledata: /tt/hashtag/posts?name=ครีมกันแดด&cursor=.. → [{author.unique_id, video_id, stats}] enqueue(unique_id) for each post
D2

그래프 확장 — 댓글러·추천유저·같은 사운드

구매
신호엔드포인트
영상 댓글러post/comments → 관심 신호 강한 계정
추천/유사 유저user/suggested · followings → BFS 확장
같은 사운드 작성자music/posts → 트렌드 참여자
이게 전수 수렴의 엔진 — D1이 씨앗, D2가 확장. 신규 발견률 <3%까지 BFS. 대부분의 볼륨과 고유성이 여기서 나온다.
D3

커머스 그물 — TikTok Shop Affiliate

공식·자격
API기능
TikTok Shop Partner (Affiliate/Seller) API카테고리별 어필리에이트 크리에이터 목록 · GMV·실적 · 초대 발송

제품·카테고리별 실제 판매한 계정을 공식 통로로. 자격(Shop 파트너) 필요. 문서의 어필리에이트 전략과 직결.

D4

커뮤니티 파싱 — FB·Threads·Zalo

구축

문서의 채널. 그룹 게시·자기소개 글에서 핸들·연락처 추출. 공식 API 제한적이라 현지 리드 수동 + 반자동 파싱 혼합. Meta Graph API(공개 그룹 한정)·Threads는 제한적.

단계 2 · Fetch — 프로필 상세 조회

핸들 → 팔로워·게시·bio·지역·링크. 벤더 라우터가 우선순위/폴백을 관리한다(한 벤더 실패 시 다음).

API반환 필드단가
EnsembleData user/info팔로워·팔로잉·좋아요·bio·공개 연락처·지역·인증유닛제
ScrapeCreators프로필 메타 전반$0.99~1.88/1K
LamatokTikTok 전용 · 프로필·검색·추천요청당
Apify 프로필 액터프로필·최근 영상·통계$2~6/1K
// 벤더 라우터 (폴백) async fetchProfile(handle): for v in [ensemble, scrapecreators, lamatok, apify]: try: return normalize(await v.userInfo(handle)) catch RateLimit|NotFound: continue return null // dead_letter 큐로
비용 최적화 — Fetch가 계정당 비용의 대부분. ① L2 라이선스 스냅샷으로 대량 계정은 fetch 자체를 스킵(가장 큼). ② 대량 구간은 ScrapeCreators($0.99/1K)로, 정밀 필드는 EnsembleData로 분리 라우팅.
04

단계 3 · Enrich — bio · 이메일 · 국가

E1 · 이메일 추출 3단

단기술비고
bio 직접 파싱정규식 [\w.+-]+@[\w-]+\.[\w.-]+ + 연락 패턴무료 · 커버리지 15~30%
link-in-bio 크롤Linktree/Beacons/사이트 크롤 → 연락 페이지 이메일 (Apify 전용 액터 존재)커버리지 크게↑
이메일 DB 조인influencers.club(18M·검증 이메일) 등 핸들 조인유료 · 고커버리지 · 상위 등급만

E2 · 이메일 검증

발송 전 필수 — 반송률이 도메인 평판을 죽인다.

기술기능
구문·MX 체크정규식 + DNS MX 조회 (자체)
ZeroBounce · NeverBounce · Bouncer실재·수신 가능·역할 계정 판별 구매

E3 · 국가 판정 (다신호 합의)

signals = [account_region, lang_detect(bio), lang_detect(captions), phone_country(bio), active_hour_tz] country, confidence = weighted_vote(signals) if confidence < 0.6: enqueue(recheck)

언어 감지는 fastText/lid 또는 CLD3(자체). 전화 국번은 libphonenumber.

단계 4·5 · Dedup · Store — 유니크 계정 원장

Dedup — 아이덴티티 그래프

기술역할
블로킹 키핸들·이메일·외부 링크·표시명 정규화로 후보 그룹핑(전수 비교 회피)
매칭 규칙 → ML초기 규칙 기반(동일 이메일/링크=동일인), 이후 확률 매칭
그래프 저장계정 노드 + "동일인" 엣지. 소스별 확인 횟수 = 신뢰도

Store — 母 DB

저장소용도
PostgreSQL (주 원장)계정 레코드 · 상태(POOL/DORMANT) · 이벤트 · append-only 로그
파생 인덱스 (OpenSearch/pgvector)국가·카테고리·영향력 필터 검색 · 콘텐츠 유사도 매칭
객체 스토리지(S3)원본 응답 스냅샷 · 감사 추적
-- creator_pool 핵심 인덱스 CREATE INDEX ON creator_pool (country, category, influence_score DESC); CREATE INDEX ON creator_pool (email) WHERE email IS NOT NULL; CREATE UNIQUE INDEX ON creator_pool (platform, platform_uid);

레이트·프록시 원칙 — 상업 벤더가 프록시·차단 리스크를 대신 지게 하는 게 1순위(그래서 벤더 우선). 자체 스크래핑은 최소화하고, 하더라도 공개 데이터·레이트 준수·주거용 프록시로. §9(법률)의 선을 넘지 않는다.

단계 6 · Outreach — 발송 · 회신

요소기술
메일 발송(ESP)문서의 TopView 벌크 · Glovek 메일(creator@glovek.space) · 또는 Amazon SES/SendGrid + 도메인 워밍업
도메인·인증SPF·DKIM·DMARC · 서브도메인 분리 · 워밍업 스케줄
틱톡 DM정책상 초안까지 · 발송은 셀러 계정 수동(에이전트 규칙)
연락 채널 전환메일→링크트리→왓츠앱(WhatsApp Business API)/Zalo/LINE→가입 (문서 검증 루트)
회신 파싱IMAP/웹훅 → 분류(관심/거절/부재/수신거부) → 母 DB 라벨
수신거부·억제unsubscribe · suppression list · 90일 재접촉 금지 (에이전트 clean 담당)
게이트 연결 — 모든 발송은 커넥션 OUTBOUND 게이트를 거친다. 母 DB에 이메일이 있다고 자동 발송하지 않는다 — 일일 상한·워밍업·unsub·게이트 승인이 앞에 있다.

09

구축 순서 · MVP

단계구축쓰는 기술
MVP (2~3주)단일 국가·단일 카테고리로 D1(해시태그)→Fetch→bio 이메일→Postgres 저장. 벤더 1~2개.ScrapeCreators + 정규식 + Postgres + cron
확장 (4~6주)D2 그래프 확장 · 벤더 라우터·폴백 · link-in-bio·이메일 DB 조인 · dedup 그래프 · 큐/워커+EnsembleData +Apify +influencers.club +Redis/Temporal
규모화 (6주+)L2 라이선스 스냅샷 대량 적재 · 지속 증분 루프 · 국가 파드 복제 · 아웃리치(ESP·게이트) · 학습 루프+ESP +프록시 +모니터링 +평가 하네스
# MVP 최소 구성 (한 파일로도 시작 가능) seeds = ["ครีมกันแดด", "รีวิวสกินแคร์"] # 태국 선케어 for tag in seeds: for post in scrapecreators.hashtag(tag, pages=50): u = scrapecreators.user(post.author) # fetch email = regex(u.bio) or crawl(u.links) # enrich upsert_pool(u.handle, u.followers, email, # store country=detect(u), score=influence(u))
판단 원칙 — 구매가 기본이다. 스크래핑 인프라·프록시·차단 대응을 직접 짓는 건 벤더보다 느리고 리스크가 크다. 직접 구축은 우리 고유 가치인 그래프 확장 로직·dedup·母 DB·스코어링·학습 루프에 집중한다. "비용 들어도 최대한"은 벤더에 더 쓰고 우리는 로직에 집중으로 실현한다.
