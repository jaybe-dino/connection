Theprlist · 브랜드와 제품별 대량 매핑

2026-10-15 · 개발 검수본. 운영 배포·실제 OAuth 연결·실제 메일 발송은 완료 상태가 아닙니다.

전체 흐름

모집 공간브랜드 → 제품 → 발신 계정명단 매핑 + 개인화중복·거부·한도 검수200명 이하 초안 분할개인별 문구 확인사용자 승인 → 순차 발송기존 발신 계정으로 회신

10,000행은 사전 검수 용량입니다. 10,000명/일 발송을 보장하지 않습니다. 고유 이메일과 실제 고유 인원도 별도 지표입니다.

어느 화면에서 어떻게 사용하는가

  1. 콘솔에서 디노 공용 모집 공간 → 메일을 선택합니다. 회사 공간은 운영 배포 후 관리자 생성과 계정 연결이 필요합니다.
  2. 위쪽 초안 양식에서 제안 브랜드·제품·발신 Gmail·제목·본문을 입력합니다.
  3. 아래 브랜드·제품 대량 매핑에 고유 매핑 키를 입력하고 현재 제안을 매핑에 추가를 누릅니다. 다른 브랜드는 작성 제목·본문을 비우고 선택해 별도 문구로 등록합니다.
  4. 시트의 이메일·매핑 키·이름·선정 이유 4열을 복사해서 명단에 붙입니다. 이름과 선정 이유는 선택입니다. 최대 50개 매핑·10,000행입니다.
  5. 전체 매핑 사전 검수에서 브랜드·제품·발신자·개인화 예시·제외 사유·계정별 잔여 용량을 검토합니다. 이 단계는 읽기 전용입니다.
  6. 검수한 전체 초안 저장 · 발송 안 함으로 저장합니다. 각 매핑은 200명 이하 배치로 분할됩니다. 한도를 초과한 명단도 초안으로 보관되며 자동 승인되지 않습니다.
  7. 배치 내 개인별 실제 문구 확인을 열어 확인합니다. 오래된 배치는 이전 배치 더 보기에서 조회합니다.
  8. 실제 발송은 별도 사용자 승인 후 내용 승인하고 순차 발송 버튼으로 실행합니다. 승인 큐 자동 재개가 켜진 운영 환경에서는 한도 안에서 재개하므로 승인 전에 확인합니다.

실제 제품 ID와 계정 ID는 서버에서 해당 브랜드·모집 공간의 소유권을 검증합니다. 브랜드 이름이 같다고 임의로 연결하지 않습니다.

이메일매핑 키이름선정 이유

이름·선정 이유는 입력 데이터만 사용합니다. 브랜드와 제품 이름은 서버 등록값으로 치환하고, 해당 브랜드 가입 링크를 서버가 추가합니다. 수신거부 링크는 실제 전송 직전에 추가됩니다.

중복·회신·스팸 관리

  • 같은 주소가 여러 매핑에 속하면 전체 충돌 행을 제외합니다. 담당자가 하나를 선택해야 합니다.
  • 중복 행, 회사·제안 브랜드의 수신거부, 최근 접촉, 다른 초안·승인 큐의 예약 대상을 분리합니다.
  • 매핑·명단·수신거부·제품·발신 연결·잔여 용량이 달라지면 기존 검수 결과로 저장할 수 없습니다.
  • 재시도는 동일 저장 요청 ID로 처리하여 초안 중복 생성을 막습니다. 중간 오류는 한 트랜잭션에서 취소합니다.
  • 발신자·제품·브랜드·개인화 문구는 저장 시 고정됩니다. 다른 계정으로 자동 우회·회전하지 않습니다.
  • 초기 시스템 상한은 실제 계정당 200통/최근 24시간, 최소 60초 간격입니다. Gmail 화면에서 보낸 메일은 시스템 집계에 포함되지 않으므로 별도 대사합니다.
  • Gmail 접수와 배달을 구분합니다. 공급자 반송·신고 자동 집계 및 RFC 8058 원클릭 수신거부 헤더는 추가 검수가 필요합니다. 도메인 인증이나 계정 수만으로 전달성을 보장하지 않습니다.

운영 반영과 롤백

시작점 태그: theprlist-bulk-mapping-base-20261015 · 기준 커밋 1344125.

추가 마이그레이션 041은 배치의 제품·매핑과 수신자별 문구, 중복 저장 기록만 추가합니다. 기존 고객 가입 단가·청구·과금 규칙을 바꾸지 않습니다.

배포 전에 발송 러너를 중지하고 DB 백업·기존 커밋·환경 설정 버전을 보관합니다. 배포 후에도 실계정 연결과 발송은 별도 승인 범위입니다. 복귀할 때 새 배치를 보존하고, 발송 큐를 정지한 상태로 호환성을 확인해야 합니다. 테이블을 삭제하거나 운영 DB를 덮어쓰지 않습니다.
