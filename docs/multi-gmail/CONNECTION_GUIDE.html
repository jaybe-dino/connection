완성한 구조

브랜드 선택 → 여러 Google 계정 연결 → 초안별 발신 계정 지정 → 내용 검토·발송 승인 → 원래 계정으로 회신

연결 계정을 각각 표시하고, 계정별 남은 한도·중지·동기화 오류·연결 해제를 관리합니다. 초안과 답장에 발신 계정을 고정합니다. 한도 소진·연결 해제 후 다른 계정으로 자동 변경하지 않습니다. 뒤늦게 다른 계정으로 수신된 답장이 이미 작성한 답장의 발신 계정과 대화 식별자를 바꾸지 않습니다.

어느 화면에서 무엇을 하나

  1. Google 관리자 → 디렉터리 → 사용자에서 각 partnerships 계정의 최초 로그인 상태를 확인합니다. 초기 비밀번호는 저장하지 않았으므로 필요한 계정만 관리자 재설정 후 사용자 직접 입력으로 로그인합니다.
  2. Theprlist 브랜드 콘솔 → 메일 → 지메일 연동 → Google 계정 추가 연결. 올바른 partnerships 계정을 선택하고 발송·수신 읽기 권한을 확인합니다. 계정별로 반복합니다.
  3. 연결·한도 새로고침에서 실제 주소, 수신 권한, 중지 상태를 확인합니다. 연결하는 브랜드의 받은편지함에 최근 30일 메일이 저장되므로 전용 업무 계정만 사용합니다.
  4. 아웃리치 메일 → 발신 Gmail 선택 → 수신자·제목·본문 → 초안 저장. 저장은 발송하지 않습니다.
  5. 사용자가 수신자·주소·조건·본문을 최종 검토한 뒤 ‘내용 승인하고 발송’을 누를 때 실제 Gmail 호출이 시작됩니다. 현 단계에서는 이 버튼을 누르지 않습니다.
  6. 대화 내역에서 수신 계정 표시를 확인하고 답장 초안을 만듭니다. ‘승인하고 발송’은 실제 발송 작업입니다. 단순 조회·동기화는 발송하지 않습니다.

운영 반영 전 확인

  • 운영 배포 승인, DB 백업 및 037_outreach_sender.sql 적용 확인.
  • GOOGLE_CLIENT_ID·SECRET, OAuth 콜백 주소, TOKEN_ENC_KEY 등 기존 운영 설정을 비밀 값 노출 없이 확인.
  • 초기에는 GMAIL_SEND_RESUME_ENABLED=0으로 승인 큐 자동 재개를 차단하고 각 계정 발송 일시 중지를 확인. 발송 버튼은 별도 사용자 검토 후 사용.
  • 이전 승인 배치 중 발신 계정이 없는 배치는 자동 재개하지 않습니다. 기존 미발송 잔여 대상·중복 이력을 검토하고 발신 계정 지정 초안으로 다시 검토합니다.
  • 이전 답장 초안 중 발신 계정이 없는 것은 실제 발송을 차단합니다. 원래 계정과 대화를 확인한 뒤 새 초안을 작성합니다.

확장 범위와 현재 한계

이번 구현은 한 브랜드에 여러 전용 계정을 연결하는 구조입니다. 같은 메일박스를 서로 다른 고객 브랜드에 중복 연결하는 기능은 허용하지 않습니다. 회사 공용 모집 계정이 여러 브랜드를 담당하려면 별도의 조직 발신 권한·브랜드 공개 범위 설계가 추가로 필요합니다.

Theprlist의 일일 한도 2→4→6→8→12→16→20 및 초안당 20명 제한을 유지합니다. 5개 계정을 만들었다고 하루 신규 1만 명 발송이 준비되는 것은 아닙니다. 대량 모집은 제공자 실제 승인 한도, 전달성, 반송·불만 억제, 전사 중복·수신거부, 회신 인력과 전환 검증을 별도 완료해야 합니다. 이번 단계에서 DB 반입·도메인 추가 구매·SES 배포는 하지 않았습니다.
