## 검수 중 실패와 처리

첫 테스트 DB는 SQL_ASCII로 생성돼 한글 마이그레이션에 실패했다. UTF-8 격리 DB로 교체했다. harvest 패키지 누락은 로컬 테스트 의존성을 설치해 해결했다. 잘못된 CSV로 게이트 반영까지 롤백되는 것을 신규 테스트가 READY로 오인했으므로, 승인 상태를 먼저 조회·확정한 뒤 원자성을 검증하도록 수정했다. 전체 회귀 중3건은 고정된 과거 마감일 때문에 실패해 테스트 fixture를 고쳤다. 실패를 무시하거나 테스트를 삭제하지 않았다.

## 출시 판정

**이번 로컬 변경은 검토 가능한 상태다. 운영 출시 승인으로 보지 않는다.** 전사 DB 병합, 월간 실인원 운영, 여러 발신자 실발송, Glovek 전송 어댑터, 자동 반송/불만 억제, 콘텐츠/주문/정산 전체 흐름은 이번에 완성하지 않았다. 현재 서비스의 실제 OAuth/runner/잔여 한도도 확인되지 않았다. 운영 배포 전 스테이징의 legacy 상태 호환·원격 변경 대조·실계정 격리·백업 복원·가입 과금 회귀를 확인해야 한다.

## 재현

프로젝트의 Python3.11 venv에 `services/core`, `services/api[dev]`, `services/harvest`, `playwright`를 설치한다. UTF-8 전용 PostgreSQL을 `/tmp/prlist-ops-pg`,55432에 준비한다. 실행: `./tests_operations/run_qa.sh`.
브라우저 스크립트의 Chromium 실행 파일은 이 Air의 기존 캐시 경로를 사용하므로 다른 환경에서는 조정한다. 운영 계정·실주소·운영 DB로 테스트하지 않는다.
